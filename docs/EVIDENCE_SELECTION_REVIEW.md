# 한국어 기사 검토와 이번 호 후보함

기본 화면은 원문 본문을 읽고 한국어로 정리한 자료다. 제목만 번역한 자료는 수집·검토 중 탭에 둔다. 전체 자료는10건씩 표시하며 표시 범위·페이지 번호·마지막 페이지를 명시한다. 원제·출처·확인 범위·제약은 상세 보기에서 확인한다. 사례 국가와 원문 언어는 검색 국가와 구분한다. 원문 검토는 독립 사실 검증이나 발행 승인이 아니다.

대표가 체크한 최대10개 기사, 순서, 기사별 메모와 구성 방향은 동일 Durable Object의 editorial_reading 테이블에 서버 저장한다. 수정은 대표 인증과 revision CAS로 충돌을 막는다. 수집일이 바뀌거나 목록에서 빠져도 선택 당시 근거를 보존한다. 클라이언트가 임의 근거를 주입할 수 없고 실제 저장된 수집 근거만 추가한다. 다른 기기의 변경과 충돌하면 최신 내용을 다시 확인하도록 알린다.

구성안 요청은 UUID로 재시도하고 후보함 revision·순서·메모를 보관한다. 조사→분석 작업만 생성하며 원고를 승인하지 않는다. 한국어 제목으로 작업을 표시하고 자료 순서와 대표 메모를 담당에게 전달한다. 서버 입력 한도를 넘는 메모는 조용히 자르지 않고 수정 요청을 돌려준다. 대표가 조사와 분석을 각각 확인한 뒤 분석 확인·이번 호 원고 작성 요청(adopt)을 해야 기존 초안 제작 단계로 이어진다. 기존 주제·원고·외부 발행은 보존한다.

한국어 reading 보강은 별도 admin-only API다. 원본 ID/URL/제목을 확인해 기록하며 본문 전체(full_text)·일부(excerpt)·제목(metadata)을 구분한다. 각 항목에 한국어 제목·요약·핵심·국내 적용 의견·한계·국가·언어·확인 시각·실패 이유, 선택적으로 실제 읽은 직접 URL을 저장한다. 기존 수집 스냅샷·후보의 문구와 대표 결정을 자동 수정하지 않는다. 대표용 서버 중계에서는 보강 쓰기 경로를 열지 않는다.

기존 task.source_reviews 한국어 해설도 유지한다. 별도 reading이 있으면 한국어 제목과 실제 국가를 함께 표시하며 원문에 연결한다. 정기 작업은 후보함 미검토를 우선 처리하고 원문 접근 실패·유료벽과 조사 한계를 구체적으로 남긴다. 승인·발송·유료 예산을 자동 확장하지 않는다.

검증은 메모리 DB와127.0.0.1 합성 환경에서 수행한다. 개발 전용 원격지 변경은 NODE_ENV=development와127.0.0.1 명시 포트로 제한되며 운영은 고정 API만 사용한다. 실제 후보 선택·대표 승인은 검증을 위해 대신 실행하지 않는다.
